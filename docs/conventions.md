# Project conventions

Conventions are enforced by tooling wherever possible. If it is not enforced, it
is a suggestion, and suggestions rot.

## Layout and naming

- Packages and modules: `snake_case`, singular (`payment`, not `payments`, unless
  the package genuinely holds a collection of things).
- Classes: `PascalCase`. Protocols are named after the role (`Clock`,
  `EventPublisher`), never suffixed `Interface` or prefixed `I`.
- Implementations name their technology: `RedisCache`, `SqlAlchemyUnitOfWork`.
- Absolute imports only. Relative imports are banned by Ruff `TID252`.
- Every module starts with a docstring explaining *why* it exists, not what the
  code literally does.

## Typing

- `mypy --strict` across `src/`. No `# type: ignore` without a reason comment.
- `from __future__ import annotations` in every module.
- Public functions annotate arguments and return types - Ruff `ANN` enforces it.
- Ports are `Protocol`s, so adapters need no inheritance and tests need no mocks
  of concrete classes.

## Errors

- Expected, business-meaningful failures subclass `DomainError`.
- Bugs and outages do not. They propagate to the boundary and become a `500`.
- Never `except Exception: pass`. The two allowed broad catches are health probes
  and the top-level handler, both of which log.

## Configuration

- Everything comes from the environment through `Settings`. No module reads
  `os.environ` directly.
- Secrets are `SecretStr`.
- Anything unsafe in production is validated at boot, not discovered at runtime.

## Logging

- `structlog`, event-name first: `logger.info("order.paid", order_id=...)`.
- Event names are `noun.verb_past_tense`, lowercase, dot-separated.
- Never log a secret, a token, a panel credential or Telegram `initData`. The
  redaction processor is a safety net, not permission.
- Every log line carries the correlation id automatically.

## Time and money

- Store UTC, always. Convert to Jalali only in the presentation layer.
- Read the clock through the `Clock` port so time is testable.
- Money is an integer number of rials. Never a float, ever.

## Tests

- `tests/unit` - no I/O, milliseconds, the bulk of the suite.
- `tests/integration` - real ASGI app, real Postgres/Redis where it matters.
- `tests/architecture` - layering and convention checks.
- Name tests after the behaviour, not the function:
  `test_readiness_returns_503_when_a_dependency_is_down`.
- Arrange / act / assert, separated by a blank line.
- Fakes over mocks. If a fake is hard to write, the port is wrong.

## Migrations

- One migration per pull request, autogenerated then reviewed by hand.
- Every migration has a working `downgrade()`.
- Data migrations are separate from schema migrations.

## Git

- Conventional Commits: `feat(billing): add wallet ledger`.
- `main` is always deployable; work happens on short-lived branches.
- Pre-commit runs exactly what CI runs, so red CI on formatting should never
  happen.
